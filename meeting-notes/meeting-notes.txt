Meeting Minutes
Discussion Points
Need to decide on the terrorist events topic and how analysis/output should be structured.
Different analysis types require different outputs (graphical, tabular, text) and different explanation formats.
Proposed design: define a “use case” that specifies the events, trace/log formats, and general workflow requirements.
Proposed design: define a “skill” per use case; each skill packages the full chain (preprocessing, mining, root cause analysis, and output generation) plus required codes/config.
Skill should also dictate data collection details (what to collect, how to save, where to save, and required formats), not only analysis.
Need a wrapper/manager layer that decides what data to collect based on the skill/use case (not just collecting data blindly).
Question about generalizing skills across customers/datasets (e.g., CMS skill using LTTNG traces) and how other companies would obtain/produce required traces.
Bottom-up approach: design for Siena/specific datasets first; later versions may merge/extend skills.
Demo/architecture presentation plan: 2–3 slides covering agent-first design, including data collection, analysis, and output under a skill.
Demo requirements: use a simple trace workflow (e.g., determine active trades/events, guide trace collection, run analysis, generate graphical/tabular/text outputs).
Implementation approach: first phase provides requirements (what events/metrics to collect in a JSON-like format); second phase executes collection, analysis, and output.
Later phase may use RAG/search; for now a simple operation can list required events/metrics based on available data.
Decisions
Adopt a two-layer design: use case definitions (requirements) and skills that package the full workflow including data collection, analysis, and outputs.
Use a bottom-up architecture approach tailored to Siena/specific datasets first, with potential merging in later phases.
For the demo, present an agent-first design with at least two example use cases (e.g., locks-related and LTTNG trace-based).
Implement a phased workflow: Phase 1 generates collection/analysis requirements; Phase 2 performs collection, analysis, and output generation.
Represent required trace/event/metric collection instructions in a machine-readable format (e.g., JSON) so the agent can drive LTTNG event selection.
