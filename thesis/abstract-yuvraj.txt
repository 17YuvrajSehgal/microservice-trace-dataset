Software systems are increasingly diagnosed by AI agents rather than by human engineers. This thesis develops agentic software observability: how an autonomous agent acquires, retains, and applies diagnostic expertise derived from past incidents, and historical root-cause analyses. Diagnosing an issue across metrics, logs, distributed traces, and kernel events requires determining which signals isolate a root cause, which events warrant collection, and which thresholds matter for a specific system. Today, this judgment remains tacit knowledge held by individual engineers or is discarded entirely once an incident resolves. Consequently, AI agents conducting root-cause analysis fail to inherit past operational knowledge, rebuilding every investigation from first principles with broad reasoning but little insight into how faults manifest below the application layer.
This thesis turns the investigation itself into a durable artifact. An observability blueprint is a self-contained, executable record of a solved issue: the condition it applies to, the telemetry required to observe it, the analysis as runnable steps, the decision rule that produces a verdict, and the boundaries under which it must not be trusted. These blueprints accumulate into a curated library that an agent selects from and executes without human intervention.
The work evaluates roughly ten classes of operational issues across microservice, monolithic, and agentic architectures. Through comparative evaluation, testing the same agent on the same incidents with and without the blueprint library against a strong deterministic baseline, this thesis establishes whether a blueprint transfers across services, whether the library abstains on uncovered problems, whether executable steps outperform prose descriptions, and whether evidence alone suffices to select the right blueprint. Ultimately, it characterizes where captured expertise accelerates diagnosis, where a capable agent succeeds without it, and where bad rules mislead.
