Software observability is increasingly being augmented with AI agents that can analyze metrics, logs, distributed traces, and kernel events to diagnose operational problems. This research will develop agentic software observability, a framework for preserving and reusing diagnostic expertise in executable form. Diagnosis depends on knowing which signals to collect, which analyses to perform, and which thresholds indicate a particular failure, and that knowledge remains largely tacit or is lost once an incident is resolved. Existing work does not preserve it: automated root-cause analysis localises faults from metrics, logs, and application traces, and recent LLM-based agents perform the same task with tool access, but in both the reusable asset is a model or a prompt rather than the investigation itself, so agents reconstruct their reasoning for each incident with little insight into how faults manifest below the application layer, a boundary at which the public datasets used to evaluate these methods also stop. What is missing is diagnostic expertise that survives an incident in executable form, evidence that it transfers to an unseen service or system, and a path by which a diagnosis informs subsequent telemetry collection. The framework's central artifact is an observability blueprint: a structured representation of the conditions under which a diagnostic method applies, the telemetry it requires, the analysis steps it performs, the decision rule used to reach a conclusion, and the boundaries beyond which it should not be trusted. Blueprints will form a curated library from which an agent can select and execute appropriate procedures, each admitted only once its signals have been measured against every issue class under study rather than the one it targets alone, together with evidence-based blueprint selection, a hierarchy for narrowing from issue classes to root causes, and a feedback mechanism through which diagnosis informs subsequent collection. The approach will be evaluated across approximately ten operational issue classes and microservice, monolithic, and agentic software architectures, using labelled fault injection and a dataset that aligns kernel events with metrics, logs, and distributed traces. The same diagnostic agent will be evaluated with and without the blueprint library and compared with a deterministic baseline, examining whether blueprints transfer across services and systems, whether the agent abstains when no suitable blueprint exists, whether executable procedures outperform prose-based knowledge, and whether available evidence is sufficient for reliable selection. The project will establish where durable, executable diagnostic expertise improves the reliability and efficiency of AI-assisted observability, where a capable agent already succeeds without it, and where an unsuitable blueprint misleads.
