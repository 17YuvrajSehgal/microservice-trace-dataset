# Reading papers

Everything cited by `blueprints/REFERENCE-PACK-FOR-KERNEL-TRACE.md`, in two views of the same
material.

```
reading-papers/
├── blueprint-references/<N> <problem>/   for READING  - one folder per blueprint
│   └── misc/                             everything the pack cites outside blueprints 1-16
├── sources/<slug>/                       for CITING   - one folder per source, no duplicates
│   ├── paper.pdf | page.html | page.txt
│   ├── paper.md  | page.md
│   └── meta.yaml
├── index.yaml                            which source supports which blueprint
└── tools/                                the manifest and the three scripts
```

**Why two views.** A source often serves several blueprints - Giraldeau 2016 supports four of
them. In the numbered folders it appears in all four, because you read by problem. In
`sources/` it appears once, because you cite by paper. Neither view is derived from the other
by hand: both are built from `tools/manifest.yaml`.

The numbered folders are the originals. `sources/` is built beside them by copying; nothing is
moved or deleted.

## meta.yaml

```yaml
slug: lo-2016-heracles
title: 'Heracles: Improving Resource Efficiency at Scale'
authors: Lo, D.; Cheng, L.; Govindaraju, R.; Ranganathan, P.; Kozyrakis, C.
year: 2016
venue: ACM TOCS (orig. ISCA 2015)
doi: 10.1145/2882783
url: http://csl.stanford.edu/~christos/publications/2016.heracles.tocs.pdf
type: peer_reviewed        # peer_reviewed | industrial | issue | doc
status: V                  # V seen  |  S snippet only  |  M from memory
verified: true             # true only when status is V
blueprints: [7]
files: [paper.pdf]
```

`type` and `status` carry over the reference pack's own tags, so a source that was read end to
end is distinguishable from one seen only in a search snippet. That is the practice the pack
itself recommends in its "best practices" section.

## Re-running

```bash
python tools/fetch_refs.py                 # download anything missing
python tools/fetch_refs.py --only 7,8      # just those blueprints
python tools/verify_pdfs.py                # is each PDF really that paper?
python tools/build_sources.py              # rebuild sources/ and index.yaml
```

All three are idempotent: a file already on disk is left alone.

To add a source, put it in `tools/manifest.yaml` and re-run. Do not hand-edit `index.yaml` -
it is generated.

## The saved pages render offline

A page saved with `curl` is only markup - images, CSS and fonts still point at the network, so
it renders bare once you are offline. The hand-downloaded pages in folders 1-6 do not have that
problem because a browser's "Webpage, complete" writes a `<name>_files/` directory beside the
html and rewrites the links to it.

`tools/complete_pages.py` does the same thing for every page fetched here: downloads each
remote image, stylesheet and script into `<name>_files/`, follows `url(...)` inside the
stylesheets so fonts and background images come too, and repoints the markup at the local
copies. **780 assets across 29 pages.** The untouched download is kept as `<name>.orig.html`,
so a bad rewrite can never destroy the only copy.

`sources/` carries the assets too, as `page_files/`, with the copy's references repointed -
otherwise the citing view would render bare while the reading view did not.

Two checks keep it honest, and both are re-runnable:

```bash
python tools/audit_html.py       # is the page real, or a challenge page / JS shell?
python tools/verify_offline.py   # does every local reference resolve on disk?
```

Current: **43 pages, 0 with a content problem, 0 bare, 0 broken content references.**

Nine references are excused rather than chased, because fetching them would change nothing on
screen:

| what | where | why it is not breakage |
|---|---|---|
| `blob:` URLs | Hazelcast page | generated by JavaScript at run time; they live only in the browser session that made them, so no server copy exists to fetch |
| 1x1 hidden images | Hazelcast page | `width=1 height=1 aria-hidden display:none` - tracking beacons, not pictures |
| `matomo.js`, `gtm.js` | USENIX page | analytics trackers. Downloadable, but an archive is better without them |

Checked by hand rather than by counter: the USENIX page has **16 of 16 images and 7 of 7
stylesheets** present, and the Hazelcast page **22 of 22 images and 2 of 2 stylesheets**. Both
render complete.

### One bug worth recording

The PSI docs page declares `canonical = https://facebook.github.io/psi/index.html` while
actually living at `facebookmicrosites.github.io`. The first version of the asset downloader
trusted that declaration, sent every request to a dead host, and quietly lost the stylesheet
and both logos - the page still "downloaded fine".

**Relative URLs resolve against where the page was fetched from, not against what the page says
about itself.** That is what a browser does. Only an explicit `<base href>` overrides it.

## Two traps worth knowing

**A valid PDF can be the wrong paper.** A guessed URL at an institutional repository returned
HTTP 200 and a perfectly good PDF - of a paper about power flow in LVDC grids, where we wanted
kernel tracing. Checking the magic bytes passes that file happily. `verify_pdfs.py` exists
because of it: it reads the first pages and looks for words the real title must contain.

**Two sources cannot be checked that way, and both are recorded as such in the manifest:**

| source | why | how it was checked |
|---|---|---|
| `turner-2010-cpu-bandwidth` | the whole 272-page OLS 2010 proceedings, not one paper | found the paper by hand on **pages 245-254** |
| `patent-11750692-conn-pool` | 21 pages of scanned images, no text layer | by eye |
