**Calibration findings (hard-won — recorded so they're never re-litigated):**
- **anomaly_disk** — containerized `stress-ng --hdd` needs `O_DIRECT`; gate relaxed 0.8→0.5
  (the QC gate is tunable; `fault_catalog.md` predictions are not).
- **anomaly_net** — `tc netem` on the **host bridge device does NOT impair L2-forwarded
  container↔container traffic**. Rewrote to per-container-netns netem across the stack;
  target = catalogue p95 (not host throughput).
- **anomaly_mem** — the hard one. `stress-ng --vm` (multi-worker) caps at ~8 GB here;
  `--bigheap` in a `--memory`-capped container passed the metrics gate but the **cgroup cap
  contained reclaim in the memcg** (OOM-killed the worker internally → **zero `mm_vmscan_`**,
  losing the kernel signature). Final recipe: **uncapped single-worker
  `--vm 1 --vm-bytes 88% --vm-keep --vm-hang 0`** → MemAvailable 0.85→0.02 **and** global
  reclaim (**2.95 M `mm_vmscan_` events**: `write_folio` 2.5 M swap-out, `lru_shrink` 105 K,
  `direct_reclaim` 3.1 K, kswapd cycling). Needs the VM's **16 GB swap** (added, persisted in
  `/etc/fstab`). Reproduced cleanly across all 3 repeats.
- **Lesson:** never bound a host-pressure fault with a cgroup cap — it moves the pressure into
  a memcg the host-wide kernel trace can't see.

### Tooling built / fixed
- **`collect_wave2.sh`** — one-command campaign orchestrator (matrix of recipe × intensity ×
  KERNEL_MEM × target_svc × repeats). Now **gzips kernel CTF post-audit** (the fix that
  unblocked disk — raw resource-stress + KERNEL_MEM runs balloon to ~20 GB; gzipped ~3 GB).
- **`KERNEL_MEM=1` knob** in `collect_trace.sh` — adds mm/reclaim/writeback tracepoints
  (this kernel has **no `kmem_*`**; the real signal is `mm_vmscan_*` + `writeback_*`).
- **`gzip_reclaimer.sh`** (on VM) — idle-priority (`nice -n19 ionice -c3`) compressor that
  gzips each run after its audit, deferring IO to the live capture. Used to keep the live
  campaign clean without kill/restart.
- **`collect_overhead.sh`** — RQ4 fair-rotated overhead wrapper (baseline / lttng_only /
  lmat_async), auto-detects the LMAT model. Built + dry-run OK.
- Full-Prometheus export (`download_metrics_full.sh`) already wired into `run_scenario.sh` →
  every run gets the whole `__name__` space automatically.
